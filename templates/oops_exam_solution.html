Question 1 A College Management System

Why OOP is Closer to Real-World Problem Solving than Procedural Programming

Definition & Core Concept

Object-Oriented Programming (OOP) models software as a collection of interacting objects, each bundling data (attributes) and functions (behaviours), just as real-world entities do. In contrast, Procedural Programming models a program as a sequence of procedures (functions) operating on detached, shared global data structures.

Why OOP is Closer to the Real World (Key Characteristics)
  • Problem domain maps directly to code: A real Student, Teacher, or Course becomes a class with the same name, so the program directly mirrors reality.
  • Data + behaviour together (Encapsulation): A real student has a name and registers for courses; OOP packages both in one unit. Procedural code keeps data in structs and logic in unrelated functions.
  • Data hiding: Real objects hide internals (you cannot manipulate another person's marks directly). OOP uses private members; procedural global data is exposed to every routine.
  • Natural hierarchies (Inheritance): Professor is an Employee; Student is a Person. Procedural code has no direct structural equivalent.
  • Same message, different response (Polymorphism): Calling calculatePay() behaves differently for a Professor versus a Clerk.
  • Bottom-up design and reuse: Engineers construct reliable, small objects first, then assemble them into complex systems.
  • Easy change and maintenance: Adding a new entity (e.g., Hostel) adds an isolated class without touching existing code.

#include <iostream>
#include <string>

class Student {                 // Real-world entity -> Class

    string name;

};

class Teacher {
private:
    string name;
public:
    Teacher(string n) : name(n) {}

    void teach(string course) {                   // Behaviour
        cout << name << " teaches " << course << endl;
    }
};

int main() {
    Student s(101, "Asha");     // Object = concrete student
    Teacher t("Dr. Rao");       // Object = concrete teacher

    t.teach("OOPM");
    s.register_for("OOPM");     // Objects interact via message passing
    return 0;
}

Question 1 B Static Polymorphism

Function Overloading and Constructor Overloading in C++

Definition & Core Concept

Function Overloading is defining multiple functions with the same name but different parameter lists (different number, type, or order of parameters) in the same scope. Constructor Overloading is defining multiple constructors in one class with different parameter lists, so objects can be initialized in different ways. Both represent compile-time (static) polymorphism.

C++ Implementation Code
overloading_demo.cpp 
#include <iostream>
using namespace std;

// ---- Function Overloading ----
int    area(int s)            { return s * s; }          // Square
int    area(int l, int b)     { return l * b; }          // Rectangle
double area(double r)         { return 3.14159 * r * r; }// Circle

// ---- Constructor Overloading ----
class Rectangle {
    int length, breadth;
public:
    Rectangle() : length(0), breadth(0) {}                 // Default
    Rectangle(int s) : length(s), breadth(s) {}            // Square
    Rectangle(int l, int b) : length(l), breadth(b) {}     // General
    Rectangle(const Rectangle &r) {                        // Copy
        length = r.length; breadth = r.breadth;
    }
    int getArea() const { return length * breadth; }
};

int main() {
    cout << "Area square: " << area(4) << endl;
    cout << "Area rect:   " << area(4, 5) << endl;
    cout << "Area circle: " << area(2.5) << endl;

    Rectangle r1;                   // Default
    Rectangle r2(5);                // Square
    Rectangle r3(4, 6);             // General
    Rectangle r4(r3);               // Copy
    cout << "Areas: " << r1.getArea() << " " << r2.getArea() << " "
         << r3.getArea() << " " << r4.getArea() << endl;
    return 0;
}
Terminal Output

Question 2 A Object Model

"Everything in OOP Revolves Around Objects": Identity, State, and Behaviour

Definition & Core Concept

An object is a run-time instance of a class that represents a real-world entity having identity, state, and behaviour. The Object Model conceptual framework views software as cooperating objects, supported by Grady Booch's 4 major principles: Abstraction, Encapsulation, Modularity, and Hierarchy.

The Three Essential Properties of an Object
Property Meaning Example (Bank Account Object)
Identity Unique existence distinguishing it from all other objects (memory address). acc1 and acc2 are distinct even if both hold ₹5000.
State Set of values held by data members at a given time; state changes over time. accNo = 101, holder = "Ravi", balance = 5000.0
Behaviour Operations the object can perform (methods); reads or modifies state. deposit(), withdraw(), checkBalance()
C++ Implementation Code
object_properties.cpp 
#include <iostream>
using namespace std;

class BankAccount {
    int accNo;              // State
    double balance;         // State
public:
    BankAccount(int n, double b) : accNo(n), balance(b) {}
    void deposit(double amt)  { balance += amt; }   // Behaviour alters state
    void show() const { cout << "Acc " << accNo << " Balance: ₹" << balance << endl; }
};

int main() {
    BankAccount a1(101, 5000), a2(102, 5000);  // Same state values, distinct identity
    a1.deposit(1000);                          // Mutates only a1's state
    a1.show();                                 // Acc 101 Balance: ₹6000
    a2.show();                                 // Acc 102 Balance: ₹5000
    cout << (&a1 == &a2 ? "Identical" : "Distinct Objects") << endl;
    return 0;
}
Question 2 B Memory Management

Student Class with Three Objects: Shared Class Definition, Individual State

Key Concept

A class is defined once. Each instantiated object receives its own independent memory block for data members (state), whereas member functions exist only once in the shared code segment. The implicit this pointer informs member functions which object to manipulate.

SHARED CODE SEGMENT (Read-Only) DATA / STACK (Per-Object Memory) +--------------------------------+ s1 (0x1000): ["Asha" | 1 | 82.5] | Student::setData() | s2 (0x1040): ["Ravi" | 2 | 74.0] | Student::display() | s3 (0x1080): ["Meera" | 3 | 91.0] +--------------------------------+ One compiled copy only Separate storage for each object
C++ Implementation Code
three_students.cpp 
#include <iostream>
#include <string>
using namespace std;

class Student {
    string name;       // Individual copy per object
    int rollNo;
    float marks;
public:
    void setData(string n, int r, float m) { name = n; rollNo = r; marks = m; }
    void display() const {
        cout << "Name: " << name << ", Roll: " << rollNo << ", Marks: " << marks << endl;
    }
};

int main() {
    Student s1, s2, s3;                 // 3 objects, 1 class
    s1.setData("Asha", 1, 82.5);
    s2.setData("Ravi", 2, 74.0);
    s3.setData("Meera", 3, 91.0);
    s1.display();
    s2.display();
    s3.display();
    return 0;
}
Question 3 A Performance & Compiler

Inline Functions for Square and Cube; Inline vs Normal Function Call

Definition & Core Concept

An inline function is declared with the keyword inline. It suggests the compiler substitute the function body directly at each call site (inline expansion) at compile time, eliminating standard call overhead (stack frame allocation, register saving, jumping, returning).

C++ Implementation Code
inline_demo.cpp 
#include <iostream>
using namespace std;

// Inline expansion request
inline int square(int n) { return n * n; }
inline int cube(int n)   { return n * n * n; }

int main() {
    int num = 4;
    cout << "Square of " << num << " = " << square(num) << endl;
    cout << "Cube   of " << num << " = " << cube(num)   << endl;
    return 0;
}

Question 3 B Enterprise Architecture

Major Features of the OOP Paradigm and How They Help Build Large Systems

8 Major Features of OOP
  • 1. Objects and Classes: Blueprint and run-time instances acting as modular building blocks.
  • 2. Abstraction: Represents essential characteristics while hiding low-level intricacies.
  • 3. Encapsulation: Wraps state and functions into one protective boundary.
  • 4. Data Hiding: Internal data is guarded from external mutation via private specifiers.
  • 5. Inheritance: Derived classes acquire properties of base classes for hierarchical reusability.
  • 6. Polymorphism: "One interface, multiple implementations" (overloading & virtual overriding).
  • 7. Dynamic Binding: Method address is resolved dynamically at runtime using vtable.
  • 8. Message Passing: Loose coupling via explicit member function requests.

Question 4 Comprehensive Program

Single C++ Application Combining Class, Object, Constructor, Destructor, Inline Function, Formal and Actual Arguments

Complete C++ Program
complete_oop_application.cpp 
#include <iostream>
using namespace std;

// ---------- CLASS: blueprint with data + functions ----------
class Rectangle {
private:                                  // Data hiding
    int length;                           // Data members
    int breadth;

public:
    // ---------- CONSTRUCTOR: formal arguments (l, b) ----------
    Rectangle(int l, int b) {
        length = l;
        breadth = b;
        cout << "Constructor: object created (" << l << ", " << b << ")" << endl;
    }

    // ---------- INLINE FUNCTION (implicitly inline inside class body) ----------
    inline int area() const { return length * breadth; }

    // ---------- Member function with FORMAL argument 'factor' ----------
    void scale(int factor) {
        length *= factor;
        breadth *= factor;
    }

    void display() const {
        cout << "Length=" << length << " Breadth=" << breadth
             << " Area=" << area() << endl;
    }

    // ---------- DESTRUCTOR: no arguments, no return type ----------
    ~Rectangle() {
        cout << "Destructor: object destroyed (" << length << ", " << breadth << ")" << endl;
    }
};

int main() {
    Rectangle r1(4, 5);     // OBJECT r1; ACTUAL arguments 4, 5
    r1.display();           // Message passing

    int f = 2;
    r1.scale(f);            // ACTUAL argument 'f' passed to FORMAL parameter 'factor'
    r1.display();

    Rectangle r2(2, 3);     // Second object with independent state
    r2.display();
    return 0;               // Automatic destruction in LIFO order (r2 then r1)
}

Question 5 B Initialization & RAII

Why a Constructor is Required in a Class

Crucial Reasons for Constructors
  • Guaranteed Initialization: Prevents data members from holding undefined stack garbage values.
  • Automatic Execution: Invoked implicitly by the runtime, eliminating human oversight of forgetting an init() function.
  • Object Integrity & Validity: Guarantees that every object begins its lifecycle in a valid state (e.g. balance ≥ 0).
  • Resource Acquisition (RAII): Acquires dynamic memory (new), opens files, or sets network connections at creation.
  • Initialization Flexibility: Overloaded constructors support default, parameterized, and copy creation.
C++ Implementation Code
constructor_demo.cpp 
#include <iostream>
using namespace std;

class Account {
    int accNo;
    double balance;
public:
    Account() : accNo(0), balance(0.0) {}                    // Default Constructor
    Account(int n, double b) : accNo(n), balance(b) {}       // Parameterized Constructor
    Account(const Account &a) : accNo(a.accNo), balance(a.balance) {} // Copy Constructor
    void show() const { cout << "Acc " << accNo << " : ₹" << balance << endl; }
};

int main() {
    Account a1;                 // Default constructor called automatically
    Account a2(101, 5000);      // Parameterized constructor
    Account a3(a2);             // Copy constructor
    a1.show(); a2.show(); a3.show();
    return 0;
}
Question 6 A Static Semantics

Static Data Members and Static Member Functions (Student Counter)

Definition & Core Concept

A static data member is a class-level variable declared with static; exactly one copy is shared universally across all objects in the data segment. A static member function has no implicit this pointer, can access only static variables, and can be invoked through the class name directly (Student::getTotal()).

C++ Implementation Code
static_student_counter.cpp 
#include <iostream>
#include <string>
using namespace std;

class Student {
    string name;
    int rollNo;
    static int totalStudents;            // Shared universally across ALL objects
public:
    Student(string n, int r) : name(n), rollNo(r) {
        totalStudents++;                 // Increments single shared copy
    }
    ~Student() { totalStudents--; }      // Decrements upon destruction
    static int getTotal() { return totalStudents; }   // Static member function
};

// Explicit external definition & allocation in Data Segment
int Student::totalStudents = 0;

int main() {
    cout << "Initial count: " << Student::getTotal() << endl;   // 0 (no objects yet)
    Student s1("Asha", 1);
    Student s2("Ravi", 2);
    Student s3("Meera", 3);
    cout << "Total students: " << Student::getTotal() << endl;  // 3

    {
        Student s4("Kiran", 4);
        cout << "Inside block: " << Student::getTotal() << endl; // 4
    }                                                           // s4 destroyed here

    cout << "After block: " << Student::getTotal() << endl;     // 3
    return 0;
}
Why Instance Variables Fail for This
  • An instance variable gets copied into each object, so s1.count and s2.count would each equal 1; neither knows the global count.
  • Instance variables cannot be read prior to creating the first object.
  • Using procedural global variables destroys encapsulation and data protection.

C++ Implementation Code
access_modifiers.cpp 
#include <iostream>
using namespace std;

class Account {
private:
    double balance;                  // Hidden: direct outside access prohibited
protected:
    int accNo;                       // Visible to derived classes only
public:
    Account(int n, double b) : accNo(n), balance(b) {}
    void deposit(double amt) {       // Controlled, validated interface
        if (amt > 0) balance += amt;
    }
    double getBalance() const { return balance; }
};

class Savings : public Account {
public:
    Savings(int n, double b) : Account(n, b) {}
    void showAcc() const {
        cout << "Acc No: " << accNo << endl; // Allowed: protected in base
        // cout << balance;                  // ERROR: private in base!
    }
};

int main() {
    Account a(101, 5000);
    a.deposit(500);
    cout << "Balance: ₹" << a.getBalance() << endl; // 5500
    // a.balance = 0;                                // COMPILE ERROR: private!
    Savings s(102, 1000);
    s.showAcc();
    return 0;
}

Employee Class: Instance Members vs Static Members

Assumption: The attributes are Employee ID, Employee Name, Basic Salary, Department, and Company Name.

C++ Implementation Code
employee_static_demo.cpp 
#include <iostream>
#include <string>
using namespace std;

class Employee {
private:
    int    empId;                  // Instance: unique per employee
    string empName;                // Instance
    float  basicSalary;            // Instance
    string department;             // Instance
    static string companyName;     // STATIC: one shared copy for all employees

public:
    Employee(int id, string name, float sal, string dept)
        : empId(id), empName(name), basicSalary(sal), department(dept) {}

    static void setCompany(string c) { companyName = c; }
    static string getCompany()       { return companyName; }

    void display() const {
        cout << "ID: " << empId << ", Name: " << empName
             << ", Salary: ₹" << basicSalary << ", Dept: " << department
             << ", Company: " << companyName << endl;
    }
};

string Employee::companyName = "TechSoft Ltd";   // External static definition

int main() {
    Employee e1(1, "Asha",  50000, "IT");
    Employee e2(2, "Ravi",  42000, "HR");
    e1.display();
    e2.display();

    // Rebranding updates all objects simultaneously
    Employee::setCompany("TechSoft Global");
    e1.display();
    e2.display();
    return 0;
}

Question 8 Lifecycle & Scope

Construction and Destruction of Objects; BankAccount Class; Block Execution Sequence

C++ Implementation Code with Resource Management
bank_account_lifecycle.cpp 
#include <iostream>
#include <string>
using namespace std;

class BankAccount {
private:
    int     accNo;
    string  holder;
    double  balance;
    string *log;                    // Dynamic memory resource

public:
    // CONSTRUCTOR: Acquires dynamic memory resource
    BankAccount(int n, string h, double b) : accNo(n), holder(h), balance(b) {
        log = new string("Account opened");
        cout << "[Constructor] Account " << accNo << " opened for " << holder << endl;
    }

    void deposit(double amt)  { balance += amt; *log = "Deposit made"; }
    void display() const {
        cout << "  " << accNo << " | " << holder << " | ₹" << balance
             << " | " << *log << endl;
    }

    // DESTRUCTOR: Releases acquired dynamic memory
    ~BankAccount() {
        delete log;
        cout << "[Destructor] Account " << accNo << " closed" << endl;
    }
};

int main() {
    cout << "--- main starts ---" << endl;
    {   // Block begins
        BankAccount a1(101, "Asha", 5000);
        BankAccount a2(102, "Ravi", 3000);
        BankAccount a3(103, "Meera", 8000);
        a1.deposit(1000);
        a1.display();
        a2.display();
        a3.display();
    }   // Block ends: Destructors invoked in reverse order (LIFO: a3 -> a2 -> a1)
    cout << "--- main ends ---" << endl;
    return 0;
}
